## What this project is

Revamp CMS ("Revamp", for ET Oneworld) is a self-serve microsite builder for event pages — lets a non-technical event owner go from "Create Event" to a published microsite without Ops keying an intake form or a developer hand-coding sections. Full detail: [PRD.md](PRD.md).

Current implementation is a **static HTML/CSS/vanilla-JS prototype** — no framework, no build step, no backend. State lives in browser `localStorage`. Full detail: [Design.md](Design.md), [architecture.md](architecture.md).

## Facts worth remembering across sessions

- **Brand/target site**: ET Oneworld — "Published. The microsite is live at etoneworld.com" (from `dashboard.html`).
- **No backend, no auth, no real persistence** — everything is `localStorage`, per-page, per-event-id. Four different access patterns exist (`RevampCore.loadState/saveState`, two page-local direct variants, payments sub-app's own).
- **Three divergent CSS `:root` palettes** (`edit-event.css`, `create-event.html`, `Event_Listing.html`) — not yet unified. Don't assume one canonical color/token source when editing styles; check which file you're in. Fonts *are* unified as of 2026-09-21 though: `--font-body`/`--font-display` are Inter in every `:root` (colors/spacing tokens still diverge).
- **CMS chrome font is Inter** (`--font-body`/`--font-display` in every page's `:root`, as of 2026-09-21) — but the **microsite preview inside `custom_editor.html`** (the `.site-section` content) intentionally uses its own separate `--site-body-font`/`--site-display-font` tokens (default Manrope/Fraunces, overridden per template — see the per-template theming entry below). Don't "fix" those to Inter; they're deliberately independent so themed content matches each real ET template's typography.
- **Event context passes via URL `?event=<id>`**, not shared state — each page independently falls back to `EVENTS[0]` if missing.
- **Create Event wizard** (`create-event.html`) is a self-contained 4-step state machine (`STEPS`, `S.step`, `goStep(n)`), independent of `RevampCore`. Step 4 hands the draft to `custom_editor.html` via `localStorage['revamp.editor.handoff.v1']` + `?from=create`; the wizard has no preview step of its own.
- **Only `custom_editor.html` declared `<meta charset="utf-8">`** — `edit-event.html` and `index.html` still don't, so their UTF-8 source (em/en dashes, `·`) renders as mojibake. `create-event.html` was fixed 2026-09-21; the other two are outstanding.
- **Stack mismatch**: the original brief recommends Next.js + Tailwind; the team built static HTML/JS instead. This has not been confirmed as intentional — flagged as an open question in both PRD.md and architecture.md.
- Active branches merge into `abhishek` (git user: abhishekrawat-dotcom); collaborators seen in commit history: ayush, vishakha, rohit.

## Work log

- **2026-09-29**: Fixed the site editor's sticky nav overlapping the page while scrolling (`custom_editor.html`). There were two causes:
  - **Transparent while stuck:** the nav background is `--site-nav-bg: transparent` by design, and the frosted `is-scrolled` state only switched on once the hero's bottom came within 80px of the stage top, so the stuck nav's links printed over the hero text. `checkMotionState()` now sets `is-scrolled` as soon as the nav is stuck (frame top above nav top).
  - **Gap above:** the nav stuck at `top: 0`, which sits below the stage's 34px top padding, so page content showed through a gap above it. The stage now defines `--stage-pad-top`, and `#frame.has-sticky-nav` nav uses `top: calc(-1 * var(--stage-pad-top))`. The preview clone's rule (`.has-sticky-nav`, no `#frame`) is unchanged.
  - **Verified headless:** at scroll 0/300/900 and in mobile view.
- **2026-09-29**: **"Pick on banner"** (option 3 of 4 discussed for layers detection can't read; the user chose it).
  - **Why it's needed:** detection reads a text layer's words, whatever the layer is named. But a date, venue or hashtag inside a "Vector Smart Object", outlined, or flattened has no words to read. Across the user's 126 PSDs: 497 live text layers, ~3,900 generic-named non-text layers, and 195 embedded `.ai` / 97 `.psb` smart objects.
  - **How it works:** a button in the Detected panel header turns on pick mode (`psdPick.on`). The upload overlay steps aside, and the canvas gets a crosshair and an accent outline. `psdLayerAt()` finds the topmost visible layer with paint within ~0.4% of the banner width of the pointer, using each raster's alpha, read once and cached; sample-banner HTML layers use their bounds. Layers covering ≥90% of the banner aren't pickable. Hovering outlines the layer with its name; clicking opens a menu with **Hide this** or **list it as Date / Venue / Hashtag / Button** (`listPickedPsdLayer`: a `picked: true` item, hidden for kinds that start hidden). If the layer is already listed, the menu offers "Hide this <kind>". Esc closes the menu, then ends picking. After a reload, pick mode re-reads the PSD from IndexedDB first.
  - **Verified headless** with `Banner.psd` and the sample banner.
  - **Still open (discussed, not approved yet):** option 1, reading the words inside embedded `.psb`/`.ai` smart objects (the `.ai` via a PDF text library); option 2, OCR (Tesseract.js); option 4, a layer-naming rule for designers (`date`, `venue`, `hashtag`, `cta`).
- **2026-09-29**: Detected panel now also finds **venues** and **hashtags**, and both start hidden, like dates (`PSD_HIDE_BY_DEFAULT`); only buttons start shown.
  - **Hashtag:** a text layer ≤40 chars containing `#tag`, or a non-text layer whose name starts with `#`.
  - **Venue:** a small text layer ≤60 chars naming a venue word, hotel chain or city (`VENUE_RE`), or containing the venue/city typed in step 1.
  - **Order and icons:** detection runs buttons → dates → hashtags → venues, so a combined "18th June, 2026 | Bengaluru" layer is one Date item. Dates, hashtags and venues all take the small icon beside them (`textItems()`), so the venue's pin hides with it.
  - **Tested:** over 126 PSDs, 12 had a venue ("Hyatt Regency, New Delhi", "Shangri-La New Delhi", "Virtual"…) and 10 had a hashtag. One false positive: "E-Revive Pune" on a non-event creative, picked up because it names a city.
  - **Verified headless** with `Banner.psd` (GMA'26): the date+icon, the venue+pin and the hashtag all start hidden, leaving the logo and artwork; switching the venue on brings back its text and pin.
- **2026-09-29**: **"Detected in your PSD" panel** (between the banner preview and the layers table). The user approved this after a discussion round.
  - **Detection:** `detectPsdItems()` now finds buttons as well as dates and returns `b.detected = [{ id, kind: 'date'|'button', label, primary, layers }]`.
    - **Button:** a short text layer (≤4 words, ≤32 chars) with button wording (`CTA_RE`: register, book, express interest, know more, watch now…) plus the button-sized shape under its centre (same group preferred, then smallest) and any non-text layer inside that shape. A non-text layer named like a button also counts.
    - **Date:** as before, plus the icon beside it.
    - **Defaults (user's choice):** dates start hidden, buttons start shown.
    - Layer text comes from ag-psd's `text.text` into `psdText`, used only for detection.
  - **Panel:** each item gets a Shown/Hidden switch that toggles all its layers together via `setPsdLayersVisible` (same composite redraw as the eyes). Hovering or focusing a row puts a spotlight (`#psd-spot`) on the item on the banner; it's dashed when the item is hidden. Layers-table rows are tagged Date / Icon beside the date / Button / Part of the button. The main layer's eye still toggles the whole item. The sample banner lists its two CTAs and the date line (set by hand in `getDefaultPsdBanner`).
  - **Tested:** against the 126 readable PSDs in the user's Downloads, a date was found in 68 and a button in 26, each paired with its background shape. Verified headless with "The Rise of the 10x Marketer.psd": toggles work, the spotlight works, state survives a reload, no errors.
- **2026-09-29**: PSD layers table: **eye toggle per layer, and date layers hidden by default.**
  - **Re-drawing:** pixel layers aren't stored on the draft, so hiding one re-draws the banner composite. `composePsd()` keeps the PSD's own composite and swaps only each hidden layer's padded area for `flattenPsd()`'s re-flatten. The flattener handles masks, clipping, opacity, group opacity and blend modes, but not layer effects. With nothing hidden it's the untouched PSD composite. Against the user's PSDs, the whole-image re-flatten matches the composite to ~0.4–2.6/255 mean difference.
  - **Persistence:** the PSD file is stored in IndexedDB (`RevampStore`, key `create:psd`, matched by `sourceKey` = name|size|lastModified), so toggles still work after a reload (`withPsdSource` re-parses it).
  - **Date detection:** `hideDateLayers()` flags small layers (≤15% of banner height) whose name/text has a month plus a digit, a numeric date, or the word "date". It also hides the small icon directly left of the date on the same row (`iconOf`), and the date's eye toggles that icon too. The sample banner's date/venue layer starts hidden.
  - **Verified headless** with `Downloads/Banner.psd` (GMA'26): the date and calendar icon start hidden while the venue and pin stay; toggles work; state survives a reload; the editor hand-off carries the result.
  - **Still open:** `collectPsdLayers` checks `l.text.value`, but ag-psd puts layer text in `l.text.text`, so every PSD text layer is typed IMAGE. That's deliberately left alone for now: "fixing" it would render the text twice (HTML text plus the text pixels baked into the composite) unless the composite also excluded text pixels.
